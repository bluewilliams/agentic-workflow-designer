# Session Bridge (one-click return path from a Claude session)

Context: no work item (direct session, director-requested: automate the mandatory copy-paste between the designer and a session; isolation between parallel workflows was a stated hard requirement). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- The refine, plan, and tuning prompts each gained one clause: ALSO drop your output into `~/.awd/outbox/{kind}-{workflow-slug}.{md|json}` (create directories; skip silently if not permitted - the run-reports posture). Clipboard instructions are UNCHANGED: the bridge is progressive enhancement, and clipboard remains the universal default.
- When the run-reports folder is connected (the same `~/.awd` - one connection powers telemetry AND the bridge; `bridgeStart()` fires from both the connect flow and the granted restore path), a 5-second poll (`bridgePoll`, hidden-paused) lists `outbox/` and surfaces matching files as a floating banner of offers: "Refined spec arrived from your session" with Apply / Dismiss. Apply routes: refined to Requirements and plan to Workflow Context (both behind the themed withConfirm - the count pin migrated 7 to 9), tuning through `importWorkflowText` (its own validation and confirms). No connection, no outbox, non-Chromium: silent no-op.
- **Isolation contract**: `bridgeExpectedNames()` recomputes the current workflow's slug-namespaced filenames on EVERY poll (a rename tracks), and only those exact names ever surface - a neighboring workflow's outputs are never read, never offered (pinned with a mixed-outbox fixture). Untitled workflows share the `workflow` slug bucket; naming the workflow isolates it.
- **Read-only posture**: the bridge deletes nothing. Applied and dismissed files are remembered by name+mtime in `awd_bridge_applied` (localStorage, try/catch, awd_ prefix), so stale files stay quiet and a NEWER drop of the same name re-offers. A connect made AFTER a session ran still finds the outputs waiting.

## Why and scope

The outbound trip was already one click (Copy); the inbound trips (refined spec to Requirements, plan to Workflow Context, tuning JSON to Import) were the fiddly half. Files-as-the-bus over the existing `~/.awd` connection reuses the run-reports transport and the monitor polling DNA with zero new infrastructure. A local server/MCP would automate the launch too and was rejected on principle 1 (zero install). Scope: three emission clauses, one scan + poll + banner + three Apply routes, CSS, help-modal sentence, pins. Non-goals: no outbound file writing from the designer, no deletion, no replacement of any clipboard flow.
