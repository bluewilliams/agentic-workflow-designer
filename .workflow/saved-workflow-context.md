# Saved workflow context (a saved workflow comes back as it was built)

Context: no work item (direct session, director-asked: do saved workflows save everything needed to represent the workflow when reloaded? Audit answer: the canvas and the workflow's own switches yes, the sidebar context the generated prompt depends on no. Director: "update it to make the most sense... so the app behaves as a user would expect", "be extra careful we don't break anything and that the fixes follow the existing architecture"). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- `serializeWorkflow` carries, beside the canvas, name, requirements, plan, repositories, and the memory/record switches, the sidebar context the generated prompt depends on, as flat top-level keys: `appSourcePath`, `appSourceBranch`, `appSourceAccess`, `uiContextNotes`, `rulesPaths`, `productDocPaths`, `verifyPaths`, `verifyNotes`, `verifyFailRun` (strict boolean), `clarifyFirst`, `approvePlan`. The same keys the machine-wide prefs (`awd_prefs`) use, so nothing new is named anywhere.
- `applyWorkflowContext(p, mode)` applies them with one rule: **a value that has something wins; an empty one never wipes what is there** (a workflow saved with no paths or notes must never erase a user's current ones, and there is no undo for that). Lists pass through `normalizePathList` (strings, trimmed, no blanks, no duplicates: the add helpers' rule applied to a whole list) and render once per group; text goes into the same DOM fields a hand edit uses; the three switches are explicit choices and always apply in restore; the access grant rides with the app path (it applies only when the save names an App Under Test path, so a save with none never revokes a grant on the user's current path; a value not among the select's options is ignored); verification notes go through `setVerifyNotes`, so validation and the status line refresh; `syncVerifyFailRunUI` runs after; the prompt refreshes once (adopt refreshes here, restore callers render right after) and prefs persist once, never during the boot-time autosave read (`_autoRestoring` clears the pending timer). `flushPendingSaves` on `pagehide` writes only what THIS tab has pending (dirty flags set by the debounce schedulers and cleared by their timers), so a reload inside the debounce windows never restores a stale snapshot over a fresher pref, an untouched second tab never overwrites what another tab just persisted, and a first visit that changed nothing writes nothing. Notes land quietly and the validation and Verifier status refresh once after the switches, so a load regenerates the prompt once, in the caller's render. Returns the item count after normalization. `deserializeWorkflow(data, opts)` calls it in `restore` mode after the canvas and repositories land, unless `opts.context === 'none'`. `openSpecAdoptContextPaths(meta)` IS the adopt rule now: it returns `applyWorkflowContext(meta, 'adopt')`, counting paths one each after dedupe, and both file imports (JSON and `awd:meta`) call deserialize with `none` and then adopt, so the toast can count what landed.
- Modes: `restore` (a saved workflow, the autosave, a clone) - every non-empty key wins, an absent or empty key leaves the current value alone, so a workflow saved before these keys existed loads exactly as before and a workflow saved with nothing in a field never wipes yours. `adopt` (the JSON import and the `awd:meta` OpenSpec import, identically) - text and lists land only where this user has nothing set; the access grant and the three switches never move (a teammate's machine paths and run posture must not clobber yours). The foreign OpenSpec import carries no sidebar context and adopts nothing.
- The two export meta lines (`# awd:meta` in the Markdown bundle and the JSON block in the schema) no longer spell the repo-path and verification keys themselves; the serializer carries them, same keys, same values.
- The Save button title and the README say what a save keeps and how old saves and imported files behave.

## Why and scope

Save and Load within one browser used to look complete only because the sidebar context persisted globally; switching between two saved workflows carried the last-used App Under Test path, UI notes, verification paths, and switches into the other workflow silently, and an exported JSON handed to a colleague carried none of them. The machine-wide defaults (default model, effort, which MCPs exist, telemetry, library favorites) stay global by design. Scope: one serializer addition, one apply helper, one optional parameter on the deserializer, three call-site modes, two export lines simplified, docs, one test. Non-goals: no new storage key, no change to prefs, no change to the OpenSpec import's adopt rule.

## Approach and decisions

- Flat top-level keys, not a nested `context` object (rejected) - the export meta already used these flat names, so the OpenSpec import's existing `openSpecAdoptContextPaths(meta)` keeps working on the same object with no translation.
- One apply helper shared with the prefs path in spirit, not by refactoring `restorePrefs` (rejected: extracting `restorePrefs`'s lines into the helper) - the director asked for care over elegance; the helper mirrors those lines and the record names them as the pair to keep in step.
- Restore for one's own saves, adopt for files from others (rejected: restore everywhere) - a colleague's JSON carries their machine paths; adopting only into empty fields is the rule the product already had for the OpenSpec path, extended to the JSON path.
- Switches never adopted from a file - clarify, approve, and fail-the-run describe how this user wants to run, not what the workflow is.
- Never wipe (round 2; the first version cleared a list when the saved list was empty) - a saved empty list or empty text leaves the current value; the three switches and the access grant still apply because they are explicit choices with no data to lose. The trade-off: a workflow deliberately saved with no paths cannot clear paths on load; the Clear-all controls do that.
- One normalizer and one refresh (round 2; the first version routed restore through the add helpers, one prompt regeneration and one prefs write per path) - `normalizePathList` applies the add helpers' rule to a whole list, rows render once per group, the prompt refreshes once, prefs persist once and never during the boot-time autosave read.
