# Default Delivery and section pins (what survives New Workflow)

Context: no work item (direct session; the director asked whether users should be able to persist defaults such as the Output node's delivery or the repo context paths, since New Workflow rightly clears the canvas but some settings get re-entered for every workflow, and what UX fits without a settings screen). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- **The model in one sentence**: the sidebar is the shop, the canvas is the job. New Workflow clears the job (canvas, name, Requirements, Workflow Context). The shop is how the director works, and every shop section carries a pin: pinned it survives New Workflow, unpinned it resets with each new workflow. One rule, no exceptions (the director's call: a preference that survives should look like every other one).
- **Defaults section** (`data-collapse-id` unchanged: `default-model`): one header, `Defaults`, with Model, Effort, and Delivery as uppercase sub-headers, so delivery is found where model and effort are. **Default Delivery**: the same fields the Output node panel shows, rendered by one shared builder (`deliveryFieldsHtml(cfg, mode)`): Format among the three deliveries (Leave Uncommitted, Commit, Pull Request), then Branching, pattern, integration, and base as the Format and strategy call for them. Never a Branch Name (a name belongs to one workflow) and never Report or Documentation (deliverable kinds, chosen on the node). Stored as `state.defaultDelivery` in the prefs; `normalizeDelivery` maps any bad stored value to the blank.
- **The Output node's Format gains `Default`**, first in the list, labelled with the current summary (`Default (Pull Request, per work item, base develop)`). `outCfg(n)` is the effective config: on Default it carries the sidebar's format, branching, base, pattern, and integration over the node's own; Deliverable and Branch Name stay the node's. Every delivery reader (branch plan, pr/commit/report/docs blocks, validation, advisor, Explain, OpenSpec summary, the `(format: ...)` lines) consults `outCfg`. The panel on Default shows the Deliverable, a one-line note linking to the sidebar section, and the per-workflow Branch Name only when the default is a single-branch Commit or Pull Request. An explicit Format shows the full fields, and when they differ from the default a `Make this my default delivery` link lifts them into the sidebar and puts the node back on Default (`adoptDeliveryAsDefault`).
- **Every code preset's Output node, Auto Workflow's Apply node, and a hand-added Output node start on Default** (`format: 'default'` replaces `'code'` at those sites). Report and docs presets keep their explicit format. A saved workflow keeps whatever it stored, so an older file with `code` still means Leave Uncommitted.
- **Section pins**: a pin glyph at the right of seven headers: Defaults (the section h3), Repositories (the section h3), Repo Context Paths (its sub-header), App and UI Context, MCP integrations, Memory and durable record, and a new two-word `Run gates` sub-header above Clarify and Approve. Pinned = accent and upright; unpinned = dim and tilted. Pinned sections survive New Workflow and keep persisting as they are edited. `state.pins` boots from `defaultPins()` (`{ defaults: true, repoPaths: true }`, everything else false), the one source, so prefs stored before pins existed boot into the same state; exactly the shipped behavior (Default Model and Effort always persisted; Repo Context Paths were already sticky). Unpinned Defaults start each new workflow from the app defaults (`NODE_DEFAULTS.agent.config.model`, inherit, Leave Uncommitted). The glyph is one `PIN_SVG` decorated onto `<button data-pin>` placeholders by `renderPins` at boot, like the collapse chevron. A click never folds the section (the collapse header skips buttons).
- **The New Workflow dialog** names what the pins keep (`Keeps (pinned): Repositories, Repo Context Paths.`); a switch section counts only when a switch differs from its new-workflow default, and Defaults never count (choices among options, not contents, and nearly every director changes one). To reset a pinned section, unpin it and start a new workflow: the pin is the whole policy, so there is no second button and no reset screen.
- **The visible shape wins** (`effectiveDelivery`): fields the Format and strategy hide read as blank in the resolver, the summary, and the equality check, so a base typed under Pull Request never leaks after the Format goes back to Leave Uncommitted; the stored values stay so switching back restores them. **Portable copies resolve Default** (`serializeNodes({ portable })`: an exported file, the awd:meta fence in the OpenSpec schema and the tuning prompt) because a file is the job and must not depend on the importer's sidebar; the autosave and the local saved list keep `default`. The new-workflow switch values live once in `NEW_WORKFLOW_SWITCHES`, read by both `clearCanvas` and the dialog's held-content check. The record path (`artifactPath`) belongs to one workflow and clears regardless of the memory pin.

## Why and scope

Every one of the preset Output nodes was created as Leave Uncommitted; a director who delivers by Pull Request per story re-entered that on every preset and every new workflow. The existing Default Model and Default Effort idiom (a sidebar default, an Inherit option on the node) already was a defaults system, so Default Delivery extends it rather than adding a settings screen: a screen separates the setting from where it is used, and needs its own navigation and save. The director chose pins on every context section over two alternatives weighed in the session: the whole sidebar persisting (no glyphs, but a stale Repositories list follows the director to the next project and lands in a prompt) and pins only on the path sections with the switches always persisting (fewer glyphs; the director preferred the flexibility). Default pin states keep the shipped behavior byte for byte. Non-goals: per-project defaults keyed by launch repo (the known hazard: defaults are global in the browser while Repositories differ per project; the dialog's Keeps line and the unpinned default mitigate it), per-role agent defaults (Default Model and Effort already cover agents; a Default Depth row with an Inherit option is the pattern if a user asks).
