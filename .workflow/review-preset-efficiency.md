# Review preset efficiency + Branch Diff Review library prompt

Context: no work item (director report: the Code Review preset took far too long for a small change). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- The Review preset is 4 agents, change-scoped end to end with an adversarial findings audit: Reviewer (changeScopedReviewer, 8 turns) -> Skeptic audit: Findings (adversary through the new 'review' lens, 6 turns, revise loop on the Reviewer behind a 'Findings sound?' gate, maxRevisions 2) -> Improver (8) -> Validator (5) -> gate -> output. The old standalone Analyzer node (10 turns of PROMPTS.codeAnalyzer whole-codebase architecture mapping before any review, regardless of diff size) is gone - its context-mapping job became the Reviewer's step 0, sized by the diff. codeAnalyzer itself is untouched (the refactoring and test generateFromStory shapes legitimately need whole-codebase analysis).
- changeScopedReviewer is the preset's edge over a plain review skill: proportionality as an explicit discipline (a 20-line fix earns a focused pass, not an architecture audit; depth goes where risk lives), five dimensions each applied-or-skipped-with-a-note, only-the-change-gates, negative findings reported, Blocking / Important / Nit severity, APPROVE / APPROVE WITH NITS / REQUEST CHANGES verdict. The preset still out-runs a bare review skill where it always did: it FIXES (Improver), validates (Validator + gate), and rides memory/records.
- The chain speaks ONE severity vocabulary: the director's tuning question exposed that Improver and Validator still hunted "Critical and High" - findings the new Reviewer never emits. Both rewritten: Improver applies Blocking-then-Important (nits only when a line or two in a touched file; no drive-by refactors; the post-fix diff must read as "the reviewed change, corrected"), Validator requires every Blocking addressed, judges Important deferrals, runs changed-area tests first then the full suite, and checks the diff stayed proportional. Test-pinned including a Critical-and-High tombstone assertion.
- Library: "Branch Diff Review" (Git & Code Review, first entry) reviews any branch against any merge target through git plumbing with a hard no-checkout contract - optional branch input (fallback: the currently checked-out branch), optional merge-target input (fallback: the repository default branch via origin/HEAD), a FEEDBACK LEVEL dial (blocking only / standard / everything - filters the write-up, never the examination; withheld severities acknowledged by count so nothing goes silently invisible), an OUTPUT FORMAT dial (numbered list / detailed report / paste-ready review comments), and the shared save-to-file checkbox. Merge-base THREE-dot diff (`git diff <target>...<branch>`), branch-tree file reads via `git show <branch>:<path>` (never the working tree), STOP-and-offer-near-matches on unknown refs, the same proportionality/discipline/verdict contract as the preset reviewer.

## Why and scope

A small change through the old preset paid for a 10-turn whole-codebase analysis before the review began - four serial agents for any diff. The fix is proportionality as prompt discipline plus one fewer serial step, keeping everything that makes the preset better than a bare review skill (fix + validate + gate + records). The library entry answers the second ask: review a branch without being on it, with a free-form merge target defaulting to the default branch.
