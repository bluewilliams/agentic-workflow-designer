# Touch-Up and Record Sync presets (amend an existing deliverable)

Context: no work item (direct session, director-requested: "a preset with agents with instructions to handle reviewing the current work and updating the durable artifacts"). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- The preset list carries a labeled group, **Amend an existing deliverable**, pinned as the list's stable bottom - after the More presets fold, so expanding More never splits the start-work presets around it (`.preset-group-label`, the uppercase divider style): every other preset STARTS work; these two change work that already shipped and keep the durable artifacts telling the truth about it.
- **Touch-Up** (`loadPreset('touchup')`): Change Request input, Touch-Up Scoper (planner, read-only tools), Amender (coder), Delta Reviewer (reviewer), a Delta sound? gate (revise loops to the Amender, maxRevisions 3), Artifact Steward (writer: technical, Read/Write/Edit/Grep/Glob), output. The Scoper grounds in `.workflow/_index.md` and `openspec/` where they exist and defines the smallest delta plus a Must Not Move list; the Amender applies it under a never-weaken-assertions rule; the Reviewer gates on regressions (materiality bars: default PASS, only Critical/High gate, a Must Not Move regression is always at least High) and lists every artifact statement the change made untrue; the Steward amends the record IN PLACE (dated History line, index facets, timeline line, openspec specs) and never mints a new record for a tweak (supersede only as an explicit, justified escalation).
- **Record Sync** (`loadPreset('record_sync')`): Sync Scope input, Drift Auditor (reviewer, refute-first: only file:line-proven drift makes the list, classified STALE/MISSING/ORPHANED), Artifact Steward, an Artifacts true? gate whose condition pins the artifacts-only contract ("no code or test files were modified"), output. Where the CODE broke the truth, the Auditor flags a defect for a follow-up Touch-Up run instead of proposing an amendment that would canonize the bug.
- The Scoper and Auditor COMPOSE their grounding from `groundingLookupSteps()` verbatim at load time (the single source of truth for the read-side protocol), with a defer-to-workflow-level clause so an orchestrator-run scan is not repeated - protocol refinements flow into these presets automatically, and a drift-immunity test pins the composition. Five new PROMPTS templates carry the craft: `touchupScoper`, `touchupAmender`, `touchupReviewer`, `artifactSteward` (shared by both presets), `driftAuditor`. Picking either preset retargets the Requirements placeholder to ask for the change AND a target hint (capability name, record slug, openspec spec or change name, ticket, files); a named target is the Scoper's PRIMARY signal, verified against the index rather than trusted blind. Absent or failing that, the Scoper locates the right record by SURFACE (files/symbols the request touches matched against index files facets, plus the timeline and `git log` for recency - so a committed tree still resolves to its record); the steward knows the openspec anatomy (`openspec/specs/` is current truth, delivered-but-active proposals in `openspec/changes/` get completed and archived per the repo's convention, and none are manufactured after the fact); the auditor treats a completed-but-still-active change as drift. All artifact references are self-gating ("where X exists", "skip silently what does not") so the presets work on greenfield repos, and all four grounding/stewardship crafts extend per-repository on multi-repo workflows (every repo keeps its own record, index, timeline; sibling cross-links stay accurate).
- Help modal: an "Amend Presets: Touch-Up and Record Sync" section under Memory, Records and Handoff (beside the flywheel it serves). README: the Built-in Presets section documents the group; preset count updated to nineteen.
- Everything else is untouched: no new toggles, no emission changes, no state shape changes - the presets compose with memory, records, grounding, and the Live Run Monitor exactly as every other preset does.

## Why and scope

Post-run follow-ups (PR feedback, small behavior tweaks) previously had no sanctioned path: a full preset was too heavy and an ad-hoc prompt bypassed the record discipline, so records drifted stale - the one failure the durable system exists to prevent. The protocol always had the amendment rules (amend in place + History line; supersede only for whole-capability replacement); these presets make the cheap path and the correct path the same path, and give SDD/OpenSpec users a first-class lane (their specs are grounded and stewarded by the same self-gating clauses). Scope: five prompt templates, two preset builders, sidebar group markup + one CSS rule, two STORY_PLACEHOLDERS entries, help and README copy, tests. Non-goals: no new record type, no touch-up companion documents (three surfaces stay three), no separate SDD mode.

## Approach and decisions

- A dedicated Artifact Steward step (rejected: folding stewardship into the Amender) - artifact truth gets a clean owner that runs AFTER the review gate, works even when the durable-record emission toggle is off, and is reusable by both presets.
- A labeled in-section group (rejected: a full sidebar section) - one-entry sections read as empty chrome; the label scales to more amendment presets and promotion later is cheap.
- Record Sync as a second preset (rejected: a mode flag on Touch-Up) - reconcile-only is a genuinely different contract (no code changes) and deserves its own gate condition.
- Static self-gating prompt language (rejected: runtime-gated emissions) - preset node prompts are user-editable text, not gated emissions; "where X exists" degrades gracefully everywhere.
