# Run-telemetry badges: tone by health, a pill above the node, the state in words

Context: no work item (direct session, director screenshot of the deployed build: 8px amber text in a 16px circle on the node outline, every badge the same color, no explanation on hover). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- A node with imported run telemetry wears a pill above its top-left corner (a diamond: centered over its top vertex), fully clear of the outline, 9px bold text, width from the text. The pill is an SVG group with a `title`, so the house tooltip delegate styles it like every other hint in the app (no native SVG title child).
- `runBadgeFor(node, rs)` decides tone, glyph, state word, and tooltip from the stats, one place for the canvas badge and the config panel line. Health needs evidence: a badge stays gray (`healthy`) until a step or gate has three runs behind it (`RUN_BADGE_SAMPLE`), whatever the numbers say, because one run is not a trend (the glyph still carries the honest figure). A reported failure is the one event rare enough to be worth a look even once: amber under the sample, red with it. With a sample, a step is `warn` (amber, `worth a look`, a warning glyph and the cap-hit count) once it has hit its turn cap, else `ok` (gray, the run count). A step with failures is `bad` (red, `struggling`, a cross and the failure count). A gate is `ok` under one revision cycle per run (a check mark when it never sent work back), `warn` at one or more, `bad` when the average reaches the node's own Max Revisions. Tones are CSS classes (`run-badge-ok|warn|bad`) so a theme fork restyles them without touching JS.
- The tooltip says what the badge is ("Run telemetry for Reviewer (2 imported run reports)" or "Gate telemetry for ..."), the state in words with the numbers behind it ("Worth a look: hit its turn cap in 2 of 3 runs. A capped step was cut short; more turns or a split may help."), and that the Tuning Prompt can act on them if the director chooses (three reports make a real sample).
- The Run Reports status line names reported steps that match no node on the canvas (sorted, up to five, computed live so a rename shows at once and a node added with the reported name clears it): telemetry is keyed by label slug, and a renamed node would otherwise drop out of the Tuning Prompt's picture without a word.
- The renderer parses the telemetry store once per node pass and hands each node its stats and the report count. The config panel Run history line carries the same state word in parentheses. The Tuning Prompt, the advisor, and ingestion are untouched: the badges are a readout of the same store, never an input.

## Why

Amber for everything made a healthy step as loud as a failing gate, `0.0x` read as an error when it was the best possible news, and the badge sat half on the outline with nothing to say on hover. Tone by health keeps healthy steps quiet and draws the eye to trouble. The pill moves the text off the outline and grows with it. The delegate tooltip was the one hint in the app still rendering the native box.
