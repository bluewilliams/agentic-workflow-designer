# New Project preset (net-new project of any shape, foundation-first)

Context: no work item (direct session, director-requested after a roster question: which preset for a net-new project? Every existing builder prompt assumes a codebase to read conventions FROM ("follow where the codebase is going", "reuse before you invent"), so the roster had no greenfield shape. Director bar: "the most comprehensive preset possible... no matter the shape of the request... clean production ready... keep the code simple and less code is usually a good thing... people look at the code produced and think: yeah, that's better than I'd have done myself"). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- A **New Project** tile (preset key `new_project`) sits in the main preset group after Full Stack Feature. Shape: Project Brief -> Project Scout -> Foundation Architect -> Skeptic gate ("Foundation sound?") -> Scaffolder -> Slice Builder -> Foundation Reviewer -> "Review OK?" gate -> Fresh-Copy Verifier -> "Project proven?" gate -> Project Ready. Seven agents. Revise and Not verified both loop to the Slice Builder, whose craft says the scaffold, README, and toolchain are also its to correct.
- Six bespoke crafts in `PROMPTS`:
  - `projectScout` (researcher, with web tools): decodes the brief into a SHAPE (CLI, library, service or API, web app, mobile app, pipeline, or a combination) and its first end-to-end slice; finds the newest sibling to mirror when an estate exists, else names the ecosystem's idiomatic default as the precedent; verifies the official generator invocation, current stable versions, layout, and the one-command toolchain against current official docs ("Memory goes stale; a wrong scaffold command wastes the whole first hour"); inventories what already exists in the target directory (never overwritten silently); runs the environment survey once for everyone; notes delivery targets only where the brief puts them in scope.
  - `foundationArchitect` (architect, with web tools): decides everything expensive to change after the first commit, under a four-line doctrine (boring by default; less code, fewer parts; ONE way per cross-cutting concern; generate then prune). Per shape it defines the first vertical slice (one real command / one public function with docs and a test / one endpoint with persistence / one screen with real data / one job end to end), the cross-cutting patterns (config via environment plus a committed `.env.example`, errors at the boundary, logging, validation at entry points, test arrangement), the toolchain as one command each with CI running exactly those, the CONVENTIONS FILE content future runs ground on (short, specific, nothing generic), an explicit not-in-v1 list, and the options that lost with reasons.
  - `scaffolder` (coder): respects what is there and initializes version control when none exists (initialize only; the delivery step owns every commit); generates with the designed invocation; PRUNES generator residue ("a stranger should find no file they have to ask about"); wires the one-command toolchain with the ecosystem's standard lint and format rules (no hand-tuned rule sets); pins versions with the lockfile tracked; `.env.example` and a complete ignore file; writes the conventions file "and nothing more"; README as a literal quickstart; CI where in scope; proves the EMPTY project passes every gate ("a foundation that fails lint on day one teaches everyone to ignore lint").
  - `sliceBuilder` (coder): the code the project is judged by. Thin and complete across every layer the shape has; reads top-down with meaningful names (no manager/helper/util/data); less code (standard library over a dependency, a function over a one-method class, every abstraction with two real callers today); follows the decided patterns exactly because the slice is the first example future code copies; errors at the boundary with real messages, never swallowed; comments say why, never what; one test per behavior with the break-then-restore discrimination check; the whole toolchain green plus the slice run as its user would; on a revise cycle fixes what was named, in the slice or the scaffold.
  - `foundationReviewer` (reviewer): reviews "as the engineer who will inherit it" - fidelity to the design and conventions file first, taste second: simplicity (speculative structure is a finding), consistency (a second pattern for any cross-cutting concern is a finding even when it works), generator residue, readability, a real toolchain, secrets (always Critical), discriminating tests, a literal README, conventions file matching the code. Default verdict PASS; only Critical/High gate; style nits are Noted, Not Gating.
  - `freshCopyVerifier` (verifier, mainline): copies exactly what version control will carry (tracked plus untracked-not-ignored, via `git ls-files -co --exclude-standard`, or the tree minus the ignore patterns when no repository exists) into a temporary path - never a clone, because the workflow's delivery step commits at the END and a clone would be empty - and follows the README word for word recording each command and exit status ("fix the README, not the reader"), runs the slice as its user would plus one failure case, checks the tree for build output, env files, and secrets, checks CI parity, cleans up. Evidence table per quickstart step and slice behavior: VERIFIED / MANUAL (never silently passed) / FAILED; verdict: whether a stranger reaches a running project from the README alone.
- `STORY_PLACEHOLDERS.new_project` asks for the project and audience, the shape, stack preferences (or "decide, boring and current"), the v1 slice, delivery target and CI scope, precedents (or "none, use the ecosystem default"), and out-of-scope.
- Both derived audit sweeps (validation warnings, advisor calibration) pass the preset without changes: the verifier's VERIFIED/FAILED table plus a Verdict line is recognized as a verdict emitter and it routes to a gate.

## Why and scope

Every existing preset reads conventions from an existing codebase; in an empty repository those instructions are inert, and nothing told the agents that their first job is to establish conventions, pick a generator over hand-rolling, and prove the project from a stranger's seat. The director's bar is a quality bar, not a feature bar: the code should read better than a good engineer would have written it, which comes from restraint (boring choices, less code, one way per concern, prune the generator) rather than ambition. Shape-agnosticism is a contract: the crafts speak of CLI, library, service, web, mobile, and pipeline and define the vertical slice per shape; they never name a vendor, framework, or package manager - the Scout's docs lookup supplies the ecosystem's defaults at run time, so the preset stays current as ecosystems move. Scope: six crafts, one builder, tile, placeholder, structure pin, crafts suite (including a vendor-neutrality pin), README bullet. Non-goals: no estate-provisioning (Platform Provisioning covers repos, pipelines, IaC in an estate; New Project is the code foundation and can follow it), no parallel lanes (a foundation is sequential by nature: scaffold before slice), no fast variant.

## Approach and decisions

- Scout before architect (rejected: architect alone) - the expensive decisions need current facts (generator invocation, versions, idiomatic layout) and the estate's precedent when one exists; verifying against current docs is the step that keeps a greenfield scaffold from being a year stale.
- Skeptic on the foundation via the existing adversary machinery with `adversaryRole:'architect'` (rejected: a bespoke critic) - the canonical skeptic already scrutinizes contracts, coupling, and boundaries; one skeptic voice app-wide.
- Scaffolder and Slice Builder as separate steps (rejected: one builder) - proving the EMPTY project green before feature code exists is the cheapest moment to fix a toolchain, and the slice deserves its own craft because it is the pattern every later file copies.
- Mainline Fresh-Copy Verifier with a bespoke prompt (rejected: review-loop verifier machinery) - the fresh-copy protocol and the README-literal contract are the preset's core proof and must be explicit.
- Loops land on the Slice Builder (rejected: separate loops to the Scaffolder) - one owner for fixes keeps the graph readable; the builder craft states the scaffold is its to correct.
- Explicit per-node tool lists (rejected: spreading AGENT_TYPE_TOOL_DEFAULTS) - every preset builder in the app states its lists explicitly; deriving them in one preset would make it the odd one, and tool selections are suggestions that never change an emitted contract.
- Vendor-neutral by pin (rejected: naming npm/pnpm/uv/cargo and popular frameworks as examples) - examples in a prompt become defaults in practice and rot as ecosystems move; the Scout's docs lookup is the source of truth.
