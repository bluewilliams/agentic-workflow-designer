# Data Migration preset: measured safety + measured success

Context: no work item (direct session, director-requested: the preset must be capable of real, shippable data-architect work - constraint and key windows included - while making an "oops" against someone's real database as unlikely as possible, and it must also maximize the likelihood of a successful delivery, not only avoid harm). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- The `data_migration` preset's shape is now recon-first and plan-gated: Migration Requirements -> Researcher -> Planner -> Skeptic gate ("Plan sound?" - the risk register's bracket/guard/fallback/proof coverage, topology fit, rollback and coupling, and the reconciliation suite) -> Migration Engineer -> Register-fidelity Reviewer gate ("Review OK?") -> Tester -> Migration Complete. Five bespoke crafts (four swapped or new plus the deepened engineer):
  - `migrationResearcher` (was generic researcher; Bash added to its toolkit): data-topology reconnaissance - the FK dependency graph, the constraint and index inventory, read-only orphan/null/duplicate probes, consumers via findReferences, conventions from precedent migrations, and volume estimates. Repository-first; a database is queried only where the requirements designate it, read-only, and "a connection string found in configuration points at real data until proven otherwise - its existence is not permission."
  - `migrationPlanner` (was generic planner): per-table strategy (expand-contract default), the **risk register** as the heart of the plan - every destructive or windowed operation (drops, truncates, type narrowing, temporary key/constraint/index windows) carries its BRACKET (re-apply in the same migration unit), GUARD (transaction, lock, or stated maintenance-window assumption), fallback, and closing PROOF - plus deploy-order coupling, the batched backfill plan, the named verification environment (so no downstream step improvises against an unknown database), the rollback map with mitigations for the genuinely irreversible, and **Done Means: the reconciliation suite** (row counts, aggregates/checksums, referential spot checks, one application-level query) - "success is measured, never assumed."
  - `migrationEngineer` (deepened): gains the **Safety boundary** (mutate only created-or-designated-disposable databases) and the **measured constraint-window craft**: temporarily dropping and re-applying keys/constraints/indexes is "legitimate craft when the work needs it" - bracketed, guarded, re-validated against ALL rows with reconciled counts; violating rows cleaned or quarantined first, orphans surfaced as a decision with counts and never silently deleted; the one named anti-pattern is dropping a constraint to make an error disappear without stating what it protected. Also: engine-native bulk paths and load-then-index ordering for large volumes ("correctness first, then the fastest safe path"). All prior craft kept verbatim (expand-contract, schema/backfill separation, lock awareness, deploy-order coupling, reversible+idempotent, edge-case documentation).
  - `migrationVerifier` (was generic tester): "proves DELIVERY, not just error-free runs." The **disposability rule**, then the **verification ladder**, climbed as high as the environment allows with the rung reported: (1) an ephemeral database the run creates itself, proving up/down/up; (2) seeded edge cases from the recon probes, the Done Means reconciliation suite, bracket-closure proofs, and DURATIONS scaled into a production-window estimate; (3) engine dry-run/lint/validate static checks with honest limits; (4) the copy-ready manual runbook - "MANUAL, never silently passed," and "an honest unrun check beats a plausible fabricated pass."
- `migrationReviewer` (was generic reviewer): "the register is your checklist, not a suggestion" - every register row's bracket located and quoted, guards verified real, proofs present as written checks, then the INVERSE sweep (any unregistered destructive or windowed operation is a finding); craft checks (real downs not stubs, idempotency, coupling both directions, reconciliation coverage, orphan handling per plan - a silent DELETE always a finding). Unregistered destruction, a bracket without its re-apply, and a stubbed down always gate.
- The "Review OK?" gate condition pins the contract: migrations match the plan, every window is bracketed with its guard and re-validation per the risk register, and no unplanned destructive operation slipped in.
- The placeholder asks for the safe test environment upfront (designated disposable database, a container the run may create, or none); the tile carries the measured-risk identity on hover.

## Why and scope

The preset had strong design craft (expand-contract, locks, deploy-order coupling) but an implicit safety model: nothing stated which databases a run may touch, the generic Tester could connect to whatever repo config named, there was no path for the no-test-database case beyond an honesty clause, and FK/constraint realities had no specific guidance. Director calibration shaped the doctrine: measured, not restrictive - constraint windows are legitimate and needed for real work; safety comes from naming, bracketing, guarding, and proving them, never from banning techniques or revoking tools. A second director push added the success half: delivery is defined (reconciliation suite) and measured (timings -> production-window estimate), not assumed. A third director push ("best it can possibly be") corrected the order to recon-first, added the Skeptic gate on the register, and made the reviewer register-aware. Scope: four new prompts, one deepened prompt, the recon-first + skeptic-gated builder, Bash for the researcher, sharpened gate conditions, placeholder line, tile tooltip and desc, craft pins, README. Non-goals: no tool restrictions, no engine-specific commands (the initial no-shape-change non-goal was deliberately superseded in the best-possible round - History has the reasoning).

## Approach and decisions

- Doctrine over tool bans (rejected: removing Bash or gating connections mechanically) - tool selections never restrict by app rule, and the real risk is judgment, not capability; the disposability rule + found-config-is-real gives the judgment a bright line.
- Bracketed windows (rejected: forbidding constraint drops - the first draft leaned that way and the director corrected it) - the anti-pattern is the unbracketed drop, so the register makes every window explicit instead of impossible.
- Ladder with a named rung (rejected: test-database-or-bust) - a run without any safe database still delivers static proof plus a copy-ready runbook, and says exactly which rung it reached.
- Delivery bar in the plan (rejected: leaving success implicit in test passes) - the reconciliation suite defines "delivered" at plan time and every downstream step executes against it.
