# Folder-pick ergonomics (hidden-folder connections without the gymnastics)

Context: no work item (direct session, director-reported pain: after accidentally disconnecting the `~/.claude/workflow-memory` watch, re-finding it required knowing Cmd+Shift+Period reveals dot folders in the macOS picker, then knowing which subfolder - "my guess is most users won't do this successfully"). Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- **Picker anchors**: `pickDirWithMemory(id)` wraps `showDirectoryPicker` for both pick flows (`awd-run-reports`, `awd-run-monitor`). Every successful pick's handle is retained in IndexedDB under `lastPick:{id}` - SEPARATELY from the live connection, so a disconnect does not lose it - and passed as `startIn` on the next pick: the dialog reopens INSIDE the hidden folder, one click from done. A cancel (AbortError) returns null without reopening; a stale anchor (any other picker error) retries once without `startIn`, and a failed retry says so in a toast (the retry can lose the consumed user activation - the button must never look dead in the recovery case). The anchor read races a 250ms timeout so a slow IndexedDB can never eat the activation before the picker opens, and the idb calls are typeof-guarded (the primitives live on neutral ground above the removable repo-connect block, preserving both blocks' removability contracts). Anchor persistence is best-effort. Chrome's own per-`id` memory (already present) remains the second anchor.
- **Split flows**: `connectRepoFolder` -> `connectRepoHandle(picked)` and `connectRunMonitor` -> `monitorAddHandle(picked)`, so the picker path and the drop path share one body (and the drop path also refreshes the anchor).
- **Folder drag-and-drop**: the monitor panel (`#monitorPanel`) and the Run Reports section (`#runReportSection`) accept a dragged folder via `getAsFileSystemHandle` (feature-detected; handle promises collected before any await, per the API's synchronous-access rule). Finder's Go to Folder (Cmd+Shift+G) reaches hidden paths trivially, so a drag from there skips the picker entirely. Text and link drags stay native (the support gate requires a file-kind item; dragover sets dropEffect copy), so a selection dragged across the sidebar can never be claimed or destroyed. Blocked locations (the browser's blocklist) get an honest denial toast via denied-counting, distinct from the drop-a-folder guidance. Both drop paths enforce their feature's support gate and surface handler failures via a catch toast. The monitor drop respects `MONITOR_MAX_WATCHES`; the repo drop takes the first folder (single connection slot) and REPLACING a live connection routes through a Replace confirm naming both folders (a drop can be accidental, and the bridge follows the connection). Dropped handles carry read permission from the gesture itself. Disconnecting the repo folder now also clears the bridge root, offers, and poll timer.
- **Point-of-action hints**: Watch Folder, + Add Folder, and Connect Folder tooltips now say the picker reopens at the last pick and that dragging from Finder works (with the Cmd+Shift+. reveal where relevant); the help modal's Connect Folder passage gains the drag alternative. Descent from a picked parent is IMPOSSIBLE for these targets: Chrome blocklists granting the home directory, so `~/.awd` and `~/.claude` have no pickable parent - anchors and drops are the whole solution space.

## Why and scope

The connection targets are hidden dot-folders under the home directory, the browser refuses to grant the home directory itself, and the picker cannot be aimed programmatically - so first-time picks needed secret keystrokes and re-picks repeated the whole hunt. Anchors make every re-pick one click; drops give a picker-free path; hints teach the first pick where the pain occurs. Scope: neutral-ground pick/drop primitives, two flow splits, container-attached drop wiring, confirm-on-replace, disconnect bridge hygiene, three tooltips, one help sentence, README passages, eight tests. Non-goals: no auto-descent (no pickable parent exists - see above); NO consolidation of `~/.awd` and `~/.claude/workflow-memory` yet - directionally right (one app-owned root would mean one connection powering monitor, telemetry, and bridge) but it is a convention migration touching every emitted prompt, run discovery, and in-flight runs, so it is parked as its own designed round, per director agreement.

## Approach and decisions

- Anchor survives disconnect (rejected: reusing the connection handle) - the pain case IS the accidental disconnect, so the anchor must outlive the thing the user destroyed.
- Cancel never retries (rejected: uniform retry) - reopening a dialog the user just closed is hostile; only a thrown non-abort error means the anchor was the problem.
- Drop listeners attach to the two STATIC containers directly (renders replace their innerHTML only, so container listeners survive every render) via `wireFolderDrop` - keeping drag-path work off the document level entirely, per the monitor block's own hot-path rule. The first draft delegated at document level with a wrong rationale; the review corrected both the code and this record.
- IDB stubbed in tests (rejected: real IndexedDB) - real IDB awaits stall under the runner's virtual-time budget and hung the whole suite; an in-memory map is deterministic and side-effect-free. The hardened runner diagnostics (same-day work) identified this failure mode on their first real outing.
