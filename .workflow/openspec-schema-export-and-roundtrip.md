# OpenSpec schema export + lossless round-trip import

Branch: main (uncommitted; Blue commits). Status: current.

## Why and scope

The workflow designer is the visual authoring layer OpenSpec lacks. This adds an OpenSpec custom-schema EXPORT (a designer workflow -> a valid `schema.yaml` + templates an `openspec` run can consume) plus a lossless ROUND-TRIP: re-import an exported schema to see/edit the visual workflow and re-export. Goal: bundle the designer's authoring benefit into OpenSpec's flow without forking the designer or breaking its single-file (no build, no deps, no backend) philosophy.

Non-goals: importing FOREIGN (non-designer) schemas - needs a YAML-subset parser, deferred to its own ticket; making OpenSpec ENFORCE per-step model/maxTurns (it has no native slot - those are forwarded as instruction INTENT only).

WYSIWYG completeness pass (2026-06-28): closed the four node-config gaps so the schema reflects what the designer shows, no matter where it runs. (1) TASK nodes are now first-class artifacts (description + acceptance criteria), wired into the requires-DAG. (2) OUTPUT nodes surface into the `apply` step as format-aware deliverable lines (PR/commit/report/docs + branch/target). (3) INPUT source guidance + the input node detail surface into the top-level `description`. (4) PARALLEL any/race join strategy is described in the branch instructions (the requires-DAG can only express wait-for-all). Export is now a real `.zip` of the `openspec/schemas/<name>/` tree (was a copy-paste `.md` bundle) so it drops straight into a repo; the YAML gained blank-line separation between artifacts and before `apply`, with the `# awd:meta` round-trip comment moved to the bottom so the human-readable schema leads.

## Approach and decisions

- Export = a sixth generator (`buildOpenSpecSchema`), surfaced as an "OpenSpec" button in the Export AREA, not a prompt tab: the output is an artifact to SAVE, not a prompt to RUN, and a button is more isolated than touching the tab render pipeline. *Rejected:* a sixth tab (breaks the "tabs = prompts" model + touches core render).
- Export file type = a real `.zip` (dependency-free store-only writer + inline CRC32), structured as `openspec/schemas/<name>/...` so it unzips straight into a repo and validates. *Forced by:* `openspec schema validate` requires `template:` on every artifact AND the referenced template files to exist on disk (both verified vs CLI 1.4.1) - so a lone `.yaml` cannot be "immediately usable"; the templates must ride along, and a zip is the only single-download way to deliver the directory structure. *Rejected:* a single `.yaml` (won't validate - missing templates); multiple sequential downloads (flat in Downloads, browser may block, user must hand-place into templates/); the old `.md` bundle (not a type openspec reads).
- WYSIWYG forwarding reuses CORE read-only helpers (`inputSourceHint`, `strategyJoinPhrase`) so the schema's wording matches the generated prompts exactly and cannot drift. Removing the OpenSpec block leaves those helpers (and all core) intact; the block depends on core, never the reverse. Task dependency resolution is the one place core could not be reused as-is (`getDepNodes` excludes tasks by contract), so a local `openSpecUpstreamWork` mirrors it + adds tasks, leaving `getDepNodes` untouched.
- Round-trip via a `# awd:meta` COMMENT carrying the full `serializeWorkflow()` JSON. Import extracts that one line and reuses the EXISTING `deserializeWorkflow` - no YAML parser, no parallel deserializer. *Rejected:* reconstructing the workflow by parsing artifact YAML (fragile, esp. literal blocks) - reserved for FOREIGN-schema import later.
- Cycle handling: `requires` = upstream agent deps EARLIER in topo order; back-edges (review loops) dropped from structure, preserved as instruction prose. *Rejected:* encoding the loop in `requires` (OpenSpec `requires` is a strict DAG - impossible).
- Config (model/tools/maxTurns) forwarded as instruction INTENT, not native fields - OpenSpec has no slot, and non-standard body fields risk `validate`. *Rejected:* `x-` body fields (unproven vs validate) and dropping the config (loses designer intent). Tools/role/loop transfer as soft guidance Claude reads; model/maxTurns are documentation on a vanilla run.
- YAML safety: instruction emitted as a literal block scalar (`|`) so arbitrary prompt content (colons, `#`, quotes) needs no escaping; single-line scalars via `JSON.stringify`.

## Gotchas

- The designer only GENERATES; `openspec schema validate` is run externally by the user/dev (single-file / no-backend philosophy intact). The CLI validation here was DEV-TIME via a temp harness, never shipped.
- `awd:meta` is a COMMENT - invisible to OpenSpec/validate; it duplicates prompts (also present in the instructions) - a deliberate tradeoff for a robust, DRY round-trip that lives in an ignored comment.
- OpenSpec does NOT enforce model/maxTurns; they ride as instruction intent + in the meta. Don't claim OpenSpec honors them.
- Foreign (non-`awd:meta`) schema import is intentionally a graceful message, not supported - it needs a YAML-subset parser (own ticket).
- `openspec schema validate` requires `template:` on EVERY artifact (a string) AND the referenced template files to exist on disk - both verified against CLI 1.4.1. So a lone `schema.yaml` cannot be "immediately usable"; that is why the export is a `.zip` carrying the templates too.
- Core `getDepNodes` excludes task nodes by contract (it feeds the 5 generators) - do NOT change it to include tasks. The OpenSpec block uses its own `openSpecUpstreamWork` instead.
- Blank lines between YAML sequence items / before top-level keys are valid and ignored by the parser; they are added purely for human readability and do not affect validation.
- Commit gotcha observed earlier: files showed `MM` (staged + newer unstaged); use `git add -A && git commit`, not a bare `git commit`. For THIS pass, Blue amends the prior commit so all OpenSpec work stays one cohesive commit (`git add -A && git commit --amend`).

## Outcome

The designer exports a workflow as a valid OpenSpec custom schema (`.zip` of the `openspec/schemas/<name>/` tree, passes the real CLI for agent/task/parallel/decision shapes) and re-imports its own exports losslessly for visual editing + re-export. Every designer node type now reflects into the schema body: agents and tasks become artifacts (full per-node config + loop/join behavior as intent), output -> apply deliverables, input -> description. Each artifact's template is a role-aware handoff/durable-record skeleton (not an empty stub), so the export visibly carries the designer's process rigor and nudges each step to leave a clean, structured record. Anything OpenSpec has no slot for still round-trips byte-exact via the ignored `awd:meta` comment. Additive, removable, core untouched (five generators + behavior unchanged; only index.html + tests.html). Foreign-schema import is the one explicit follow-up.
