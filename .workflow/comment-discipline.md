# Comment discipline (the existing instruction moves to the step briefs, where the agents that write code read it)

Context: direct session, director-requested. The director first suspected more narrating comments in recent runs, checked the outputs, found them clean, and chose to close the structural gap anyway because the instruction was not reaching the agents it was written for. Branch: main. Status: current. Repo: agentic-workflow-designer.

## Current behavior

- The comment-discipline paragraph that opened the orchestrator's Conventions block since June (prefer self-describing code over comments, in tests as much as in production code; comment only when it earns its place: a genuinely non-obvious why, a real gotcha, or a public or exported API surface; never restate what well-named code already says; no ticket IDs or changelog notes in comments; TODO only for a genuine follow-up) now lives in one layer, like the found-defect protocol: `COMMENT_RULE_TEXT` is the line every code-changing step brief carries, word for word, labelled **Comment discipline**, and the header no longer repeats it. The Conventions block keeps its test-convention discovery paragraph.
- `commentStepHint` is emitted beside the found-defect note at the same six step sites in the prompt, Sub-Agents, Agent Teams, and Claude formats. The found-defect role set carries the discipline (coder, backend, frontend, general, tester, debugger, verifier: every role that may change code, since the debugger writes a reproduction test and the verifier a harness); the reviewer role carries the review discipline below; every other role carries nothing. The SDK format is unchanged (it carries no per-step hints by owner priority; its conventions header already holds the paragraph).
- Reviewer templates keep their own comment check (role text), and the Test Reviewer, the one reviewer template without a comment bullet, gets the base reviewer's bullet inline as item 15, matching its siblings. The reviewer step line (`COMMENT_REVIEW_RULE`) carries only the cross-cutting gate mechanics, at every defect posture (posture governs pre-existing defects; comments a change adds are part of the change): a few narrating or redundant comments are a Nit, noted when the change passes and listed with the must-fix items when the verdict already sends the change back, so the same revision removes them; a pattern blocks on its own, five or more across the change, or a file whose added comments narrate most of its added code. The materiality bar and the defect posture are untouched.
- No instruction was reworded. The paragraph moved from the header to the steps; the reviewer bullets read as before (plus the Test Reviewer's new one); the SDK format is unchanged (no per-step hints by owner priority, the paragraph stays in its code header). No agent reads the same comment sentence twice in any format. The Explain report gains a Comment discipline row per node and its Conventions row says where the discipline now rides.

## Why and scope

The instruction was right and had been there since June, but only the orchestrator read it: a dispatched coder, tester, or frontend step sees only its own brief in every mode, so no writer ever saw it. Scope: the step emission, the header move, the reviewer mechanics line, the Test Reviewer bullet, the Explain rows, tests, golden recapture. Non-goals: no rewording of existing instructions, no per-agent template copies, no toggle, no change to the materiality bar or the defect posture.

## Approach and decisions

- Generated, not copied, and one layer per rule: injected by the generator like the found-defect note, which is how every cross-cutting instruction reaches an agent here, so no template holds a copy and the header does not repeat it (director: "I thought we weren't going to copy this to each agent manually"; "I also like consistency"). Duplication audit before the move: the single-session Claude agent read the paragraph once per step plus once in the header; the base reviewer read its bullet twice. Both gone.
- The existing words, unchanged, in both lines (director: "our old words better describe what I want the spirit of our agents to do"; "use wording like the wording I see in the code already"). A compact rewrite, a handoff self-check sentence, and a review line in new words were tried and reverted.
- A few comments ride a revision, a pattern blocks: the one way to send work back for comments without moving the materiality bar (director: "if it's just one extra comment we only send it back if the reviewer is already sending it back ... but if there are lots of extra comments it will, even if the defect posture is set to Surgical").
- The discipline rides the existing found-defect role set rather than a list of its own (director: "are you sure other agents like debugger don't need this instruction?": the debugger writes a reproduction test, so it does).
